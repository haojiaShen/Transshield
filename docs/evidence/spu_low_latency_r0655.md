# SPU 低延迟 r=0.655 组合档验证

## 结论

在不改变模型权重、10 层执行深度、CHEETAH/Ferret、FM64/fxp16、秘密模型参数、party-local 输入分片和 final-logits-only reveal 的前提下，将已验证的任意长度精确选择网络与 `base_rate=0.655` 组合，可把 token 保留数从 `137/96/67` 调整为 `128/84/55`。

该组合被保留为**显式启用的低延迟档**，不替换正式展示默认档。正式默认仍是 `base_rate=0.7`、`137/96/67` 和阈值 `0.6619606018066406`；低延迟档必须同时使用从 524 样本校准得到的公开阈值 `0.688152923150007`。

## VPS 结果

环境：16 vCPU Intel Xeon Platinum、约 61.4 GiB、Python 3.9.25、SPU 0.9.3b0、JAX/JAXLIB 0.4.30、CHEETAH + YACL Ferret、FM64/fxp16。模型测试全部在 VPS 执行。

| 指标 | 报告原始口径 | 当前 r=0.7 主线 | r=0.655 低延迟档 |
|---|---:|---:|---:|
| medical32 总安全前向 | 2849.945 s | 1463.214 s | **1151.815 s** |
| 每样本安全前向 | 89.061 s | 45.725 s | **35.994 s** |
| loopback 通信 | 84.466 GiB | 53.036 GiB | **50.407 GiB** |
| medical32 阈值准确率 | 93.75% | 96.875% | **93.75%** |
| medical32 AUC | — | 0.9844 | **0.9766** |

相对当前 r=0.7 主线，低延迟档的 medical32 安全前向减少 21.28%，通信减少 4.96%；相对报告原始口径，安全前向减少 59.58%，通信减少 40.32%。单样本热缓存从 86.641 秒降至 73.604 秒，减少 15.05%。

精度需要按两种证据分别解释：

- medical32 使用预注册的 r=0.655 阈值后为 93.75%，与报告原始准确率相同，但比本轮 r=0.7 主线的 96.875% 低 3.125 个百分点。
- 524 样本校准中，r=0.655 的最佳阈值准确率为 91.985%，r=0.7 为 92.748%，差 0.763 个百分点；五折交叉验证均值为 91.608%。

因此该档可以表述为“以小幅精度/AUC变化换取约 21% 的当前主线时延下降”，不能表述为无损加速，也不应替换正式结果表。

## 使用与回退

低延迟展示必须同时指定剪枝比率与对应阈值：

```bash
python3 tools/start_showcase_spu_demo.py \
  --token-ratio-base-override 0.655 \
  --threshold-json configs/transshield_runtime/medical_low_latency_r0655_threshold.json
```

不传这两个参数即保持正式默认档。runner 级复现实验使用：

```bash
--spu-secure-pruning-network unpadded_selection \
--token-ratio-base-override 0.655
```

完整结构化数据、原始 candidate JSON/PT、网络快照和 time log 位于 `results/vps_optimization/unpadded_r0655_20260802_v1/`。

## 被否决的底层候选

- SPU 0.9.5 原生秘密排序：196×384 的局部微基准明显更快，但整图单样本热缓存为 89.422 秒，比当前 86.641 秒慢 3.21%；通信增加 24.22%，因此未升级正式 runtime，也未跑 medical32。
- 单 mux 加减恢复：局部剪枝算子只从 13.601 秒降到 13.334 秒，约 1.97%，说明 SPU 已完成大部分 select 优化；未继续花费完整模型长测成本。

以上否决避免了把“局部算子更快”误写成“端到端更快”。
