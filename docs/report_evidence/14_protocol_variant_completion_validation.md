# 协议变体补跑完成记录（2026-05-19）

## 1. 本次补跑目的

本次补跑只处理两类问题：

- **已经完整跑通过且收益不足**：直接移出当前采用候选；
- **之前没有完整跑完**：修到能够完整跑通，再判断是否保留。

对应三个协议候选的最终处理方式如下：

- `mixed_compare_mode`：历史上已经完整跑通过，只有约 `1.033x` 轻微加速，且当前官方 packaged runtime 不再暴露该字段；本轮不再重开。
- `disable_matmul_pack`：之前只在批次规模 `8` 下崩掉；本轮改用 `SPU_BATCH_SIZE=1` 完整补跑。
- `SPU_BB_TRUNC_SIGN_HINT=positive_when_unknown`：之前卡在 `libspu.so` 重编链；本轮先修通重编链，再做完整补跑。

## 2. 本轮修复内容

### 2.1 服务器实验运行链修复

为了让 `trunc-positive` 能真正进入端到端执行，本轮在服务器实验分支上完成了以下修复：

- 修复 `/data/wyb/spu_src/src/libspu/mpc/cheetah/arithmetic.cc` 与旧版头文件不一致的问题；
- 用 `Bazel 7 + standalone CppCompile` 成功重编 `//spu:libspu.so`；
- 在实验运行时增加 `spu/api.py` 兼容层，使重编产物能被现有 Python 分布式运行链调用；
- 补跑结束后，已把服务器 `site-packages/spu/` 恢复回原官方运行库，避免影响正式主线。

### 2.2 为什么 `pack-off` 改成批次规模 `1`

原批次规模 `8` 的代表路径已经有明确失败证据：关闭 packing 后节点通信直接失稳，`gRPC Socket closed`，不能作为“完整跑完”的证据。

因此本轮把目标改成：

- 保持同一医疗 `depth10 dynamic secure pruning + full privacy` 语义；
- 仅把 `SPU_BATCH_SIZE` 收到 `1`；
- 先验证该候选在低批量部署档位下能否**完整执行**；
- 若能完整执行，再比较是否有真实收益。

## 3. `disable_matmul_pack` 补跑结果

结论：

- 该候选在 `1` 样本 + 批次规模 `1` 下已经可以完整跑通；
- 时间上比 baseline 更快；
- 但通信量约增到 baseline 的 `3.01x`。

### 3.2 `2` 样本 + 批次规模 `1`

| 配置 | elapsed_sec | sec/sample | 双向通信总量 |
|---|---:|---:|---:|
| baseline | `357.32` | `178.66` | `6.56 GB` |
| pack-off | `281.37` | `140.69` | `19.93 GB` |

结论：

- 在 `2` 样本 + 批次规模 `1` 下仍然能够完整跑通；
- `sec/sample` 继续优于 baseline；
- 但双向通信总量继续放大到 baseline 的约 `3.04x`。

### 3.3 对当前主线的判断

`disable_matmul_pack` 现在已经不是“没跑完”，而是“**低批量下能跑通且有时间收益，但不适合作为当前正式默认配置**”。

原因有两条：

1. 当前正式医疗复核配置仍以批次规模 `8` 的代表路径为主，而 `pack-off` 在该路径下已经明确失稳；
2. 即使在批次规模 `1` 下时间更快，通信量也显著放大，不符合当前主线更看重的稳定部署边界。

因此它的最终归类应为：

- **完成验证**
- **不进入当前正式主线**
- **保留为低批量部署档位的研究候选**

## 5. `mixed_compare_mode` 的最终处理

`mixed_compare_mode` 本轮没有再重开，原因不是“还没完成”，而是它已经具备足够的历史完整证据：

- `2026-05-12` 历史服务器实验已完整跑通；
- `1` 样本低批量复核只得到约 `1.033x` 的轻微加速；
- 后续又确认原生 `MsbA2B` 已经是高效 MSB-only 路径，先前“数量级通信下降”的解释已经撤回；
- 当前官方 packaged runtime 也不再直接暴露 `mixed_compare_mode` 字段。

因此它应直接归类为：

- **已完成验证**
- **收益不足**
- **不再进入当前部署链**

本轮协议候选补跑完成后，三者的状态已经全部明确：

- `mixed_compare_mode`：**历史已完整验证，收益不足，移除**
