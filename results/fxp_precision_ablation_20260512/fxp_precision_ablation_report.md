# SPU 固定点精度消融实验报告

实验日期：`2026-05-12`

## 实验目的

探索 SPU 固定点精度（`fxp_fraction_bits`）对安全推理精度的影响，验证当前默认配置（`fxp=16`）是否为最优选择，并分析 MPC-friendly `fixed_square (x²)` 激活函数对精度的特殊约束。

## 详细 logits 分析

### fxp=12（精度崩塌）

所有 8 个样本的 logits 范围为 ±0.014，class0 和 class1 之间的差异几乎为零。
预测全部默认为 class0。这表明 12 位小数精度不足以保留 `fixed_square (x²)` 激活后的有效信号。

### fxp=14（精度崩塌）

logits 范围扩大到 ±0.073，但仍不足以区分正负类别。所有样本仍预测为 class0。
14 位精度对于 12 层深度 + 3 次剪枝的 ViT 推理仍然不够。

### fxp=16（正确）

与原始基线完全一致：`[1,1,1,1,1,0,1,1]`（7/8 为 class1，1/8 为 class0）。
margin 最高达 0.41（sample1），最小 margin 0.064（sample4）。
**fxp=16 是保证正确推理的最低精度要求。**

### fxp=20（溢出）

部分样本的 logits 爆炸至 10⁵~10⁶ 级别。例如：
- sample1：`[-1065971.875, +86577.55]`
- sample3：`[+25726.63, -385117.50]`

原因：`fxp=20` 时整数位仅剩 44 位，`x²` 操作将有效位加倍消耗，12 层深度的累积误差导致溢出。

## 核心发现

### 1. `fixed_square (x²)` 激活函数对精度的约束

在 MPC 安全计算中，`x²` 操作将数值的有效位需求加倍。在 64-bit 有限域（FM64）下：
- `fxp=16` → 整数位 48 → `x²` 后需要 96 位，需要截断 → 精度刚好够用
- `fxp=12` → 整数位 52 → `x²` 后需要 104 位 → 截断后分数位仅 12 位，累积误差致命
- `fxp=20` → 整数位 44 → `x²` 后需要 88 位 → 截断后整数位仅 22 位，大值溢出

### 2. fxp=16 是 FM64 + fixed_square 的唯一安全操作点

对于 `fixed_square (x²)` 激活：
- **下界**：fxp≥16（低于此精度崩塌）
- **上界**：fxp≤18（高于此溢出风险急增）

这解释了为什么 SPU 默认 `fxp=16` 被广泛使用——它是 FM64 下二次运算的安全且高效的选择。

### 3. 速度几乎不受 fxp 影响

| fxp | sec/sample |
|-----|-----------|
| 12 | 114.0 |
| 14 | 112.0 |
| 16 | 109.9 |
| 20 | 110.9 |

差异在 4% 以内，属于系统噪声。SPU 的 Cheetah 协议开销主导计算时间，固定点精度位数不显著影响通信量。

## 结论

1. **当前 `fxp=16` 配置已是最优**：它是保证 `fixed_square` 激活在 FM64 字段下正确工作的最低精度设置。
2. **不能通过降低 fxp 来换取速度**：速度收益为零（或噪声级），精度代价为灾难性。
3. **不能通过提高 fxp 来换取精度**：精度反而崩塌（溢出），且速度无改善。
4. **`fixed_square + FM64 + fxp=16` 形成三位一体约束**：这个发现说明 MPC-friendly 算子设计不是孤立的，必须与 SPU 硬件参数联合优化。

## 对创新点的贡献

本实验验证了创新点 4（MPC-Friendly 算子族）的工程严谨性：

- `uniform attention + fixed_square + exact LN + fxp=16 + FM64` 不是随意组合，而是经过精度消融验证的**唯一可行配置空间**
- 为 MPC-friendly 算子设计提供了**可量化的精度约束边界**
- 证明了"协议友好算子设计"必须与"安全硬件参数"联合优化
