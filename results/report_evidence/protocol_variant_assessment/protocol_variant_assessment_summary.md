# 协议变体服务器验证摘要（2026-05-19）

## 基线
- 原正式代表路径：医疗 `depth10 dynamic secure pruning + full privacy`
- 旧 `8` 样本代表复核、批次规模 `8` 的基线：`719.26s`，`89.91s/sample`
- 补跑对照基线：批次规模 `1` 下新增 `1` 样本 / `2` 样本两组完整对照

## mixed compare
- 历史服务器实验已经完整跑通；
- 历史 `1` 样本低批量复核只有约 `1.033x` 轻微加速；
- 当前官方 packaged runtime 也不再直接暴露 `mixed_compare_mode`；
- 结论：**已完整验证，但收益不足，关闭。**

## disable matmul pack
- 旧批次规模 `8` 的代表路径：仍会失稳，不能作为正式默认项。
- 本轮补跑批次规模 `1`：
  - `1` 样本：`193.08 -> 158.02s/sample`
  - `2` 样本：`178.66 -> 140.69s/sample`
- 但通信量约放大到 baseline 的 `3x`：
  - `1` 样本：`3.32 GB -> 10.00 GB`
  - `2` 样本：`6.56 GB -> 19.93 GB`
- 结论：**已完整验证；低批量下有时间正信号，但当前正式批次规模 `8` 路径不稳定，不进入主线。**

## positive-domain truncation override
- 本轮已修通实验运行库并完成端到端补跑。
- 批次规模 `1` 对照结果：
  - `1` 样本：`193.08 -> 199.12s/sample`
  - `2` 样本：`178.66 -> 179.86s/sample`
- 通信量几乎不变，没有观察到收益。
- 结论：**已完整验证，但同条件下无收益，关闭。**

## 当前结论
- 当前正式主线继续保留默认 Cheetah packed matmul。
- ABY2.0 mixed compare 不再进入现部署链。
- positive-domain truncation scheduling 不再保留为待定候选。
- `pack-off` 只保留为低批量部署档位的研究记录，不升级为正式默认配置。
